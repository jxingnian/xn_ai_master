# 第 2 阶段：平台功能层——设置模块开发落地方案

## 1. 阶段定位

本方案对应项目开发第 2 阶段：平台功能层中的设置模块。

阶段编号：02
阶段名称：平台功能层——设置模块
文档版本：V1.0
制定日期：2026-10-30

核心层已经具备以下功能：

1. 管理员登录和 JWT 认证。
2. 应用商店列表。
3. 应用安装、启用、停用和卸载。
4. 应用配置持久化。
5. 动态菜单加载。
6. 管理员权限校验。

本阶段不开发设备管理、MQTT、OTA、告警、报表和 AI 应用生成，先完成平台自带的设置功能。

## 2. 第 2 阶段建设目标

完成后台设置模块，包含以下功能：

1. 系统状态查询。
2. 平台健康检查。
3. 管理员账号设置。
4. 审计日志。
5. AI 服务配置。

第 2 阶段完成后，平台应能独立完成基础运维和管理员配置，再进入第 3 阶段的设备管理应用开发。

## 3. 第一项：系统状态接口

### 3.1 后端文件

新增以下文件：

```text
backend/src/platform/settings/settings.module.ts
backend/src/platform/settings/system/system.controller.ts
backend/src/platform/settings/system/system.service.ts
```

修改以下文件：

```text
backend/src/app.module.ts
```

### 3.2 接口

```text
GET /api/health
GET /api/settings/system/status
```

`/api/health` 不要求登录，用于 Docker、Nginx 和部署检查。

`/api/settings/system/status` 必须经过 JWT 校验，只允许管理员查看详细信息。

### 3.3 返回内容

系统状态接口必须返回：

1. 主机名。
2. 操作系统名称和版本。
3. CPU 架构。
4. 系统运行时间。
5. CPU 使用率和系统负载。
6. 内存总量、已用内存和可用内存。
7. 磁盘总量、已用空间和可用空间。
8. PostgreSQL 连接状态。
9. 后端服务状态。

### 3.4 实现方式

1. 使用 Node.js `os` 模块读取主机、操作系统、CPU、内存和运行时间。
2. 使用 Node.js 文件系统 API 读取磁盘容量。
3. 使用 TypeORM `DataSource.query('SELECT 1')` 检查 PostgreSQL。
4. 数据库连接失败时返回明确的错误状态和错误信息。
5. 不执行未经固定白名单限制的 Shell 命令。

## 4. 第二项：管理员账号设置

### 4.1 后端接口

```text
GET   /api/auth/profile
PATCH /api/auth/profile
POST  /api/auth/password
POST  /api/auth/logout
```

### 4.2 前端文件

新增：

```text
frontend/src/platform/settings/AccountSettings.vue
```

修改：

```text
frontend/src/platform/settings/Settings.vue
frontend/src/core/layout/Layout.vue
```

### 4.3 功能要求

1. 查看管理员账号和邮箱。
2. 修改管理员邮箱。
3. 修改登录密码。
4. 修改密码时必须验证旧密码。
5. 密码使用 bcrypt 哈希保存。
6. 接口响应禁止返回密码和密码哈希。
7. 登出时删除前端本地 Token。

### 4.4 页面结构

设置页面使用 Tab 分为：

1. 账号设置。
2. 系统状态。

## 5. 第三项：系统状态页面

### 5.1 前端文件

新增：

```text
frontend/src/platform/settings/SystemStatus.vue
```

修改：

```text
frontend/src/platform/settings/Settings.vue
```

### 5.2 页面内容

页面显示以下卡片：

1. 后端服务状态。
2. 数据库连接状态。
3. 主机信息。

4. CPU、内存和磁盘使用率使用百分比和进度条显示。

## 7. 第五项：AI 服务配置

### 7.1 数据实体

新增：

```text
backend/src/entities/ai-config.entity.ts
backend/src/entities/ai-call-log.entity.ts
```

### 7.2 后端接口

```text
GET  /api/settings/ai
PUT  /api/settings/ai
POST /api/settings/ai/test
GET  /api/settings/ai/logs
GET  /api/settings/ai/usage
```

### 7.3 配置字段

```text
provider
base_url
api_key
model
temperature
max_tokens
enabled
```

### 7.4 安全要求

1. API Key 必须加密保存。
2. 查询配置时只返回脱敏后的 API Key。
3. 日志中禁止记录完整 API Key。
4. 测试接口返回连接结果、响应时间和明确错误原因。
5. 配置修改必须写入审计日志。

## 8. 后端模块注册顺序

按以下顺序注册模块：

1. 在 `settings.module.ts` 注册系统状态控制器和服务。
2. 在 `app.module.ts` 引入 `SettingsModule`。
3. 注册系统状态接口。
4. 注册账号设置接口。
5. 注册审计日志实体和服务。
6. 注册 AI 配置实体和服务。

## 9. 第 2 阶段开发顺序

必须按照以下顺序实施：

1. 完成系统状态后端接口。
2. 完成 `/api/health` 健康检查。
3. 完成账号设置前端页面。
4. 完成系统状态前端页面。
5. 完成审计日志实体、服务和查询接口。
6. 将认证和应用管理操作接入审计日志。
7. 完成 AI 配置实体和接口。
8. 完成 AI 配置页面。
9. 执行后端编译和 Docker 构建。
10. 完成接口联调和本阶段验收。

## 10. 第 2 阶段验收标准

1. `/api/health` 可以在未登录状态下返回服务健康状态。
2. 管理员可以查看主机、CPU、内存、磁盘和数据库状态。
3. 管理员可以修改邮箱和密码。
4. 错误旧密码不能修改新密码。
5. 管理员可以查看审计日志并按条件筛选。
6. 管理员可以保存、修改和测试 AI 配置。
7. API Key 查询时已脱敏。
8. 登录、改密、应用管理等操作都有审计记录。
9. 后端编译成功。
10. Docker Compose 构建和启动成功。
11. 所有接口错误返回明确 HTTP 状态码和中文错误信息。

## 11. 第 2 阶段完成后的第 3 阶段

本阶段完成后，进入应用程序层，第一项开发内容为设备管理应用：

1. 设备信息 CRUD。
2. 设备分组。
3. 设备状态。
4. 设备操作日志。
5. 设备应用菜单和权限。

设备管理应用必须以独立应用形式接入应用商店，不直接写入平台核心模块。
