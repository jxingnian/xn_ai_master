# 云端完整清理重新部署说明

## 一、重要说明

本项目使用 `build/install.sh` 执行云端完整清理和重新部署。

脚本会删除以下本项目资源：

- systemd 服务：`xn-platform`
- 安装目录：`/opt/xn-platform`
- 前端发布目录：`/var/www/xn-platform`
- Nginx 配置：`/etc/nginx/conf.d/xn-platform.conf`
- PostgreSQL 数据库：`xn_platform`
- PostgreSQL 用户：`xn_platform`

数据库 `xn_platform` 中的旧数据会被永久删除，执行前必须确认云端旧数据不再需要。

## 二、首次配置 Windows SSH 工具

一键上传部署脚本运行在本地 Windows 电脑上，需要 Windows OpenSSH Client 提供 `ssh`、`scp` 和 `tar` 命令。

在 PowerShell 中检查：

```powershell
ssh -V
scp -V
tar --version
```

如果命令不存在，请在 Windows 设置中打开“可选功能”，安装“OpenSSH 客户端”。安装后重新打开 PowerShell。

首次连接服务器时，先手动测试 SSH：

```powershell
ssh root@你的服务器IP
```

输入服务器密码并确认可以登录后，输入以下命令退出服务器：

```bash
exit
```

## 三、一键上传并部署

在本项目根目录打开 PowerShell，执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\build\deploy-to-server.ps1 -Server 你的服务器IP
```

例如：
powershell -ExecutionPolicy Bypass -File .\build\deploy-to-server.ps1 -Server 111.228.3.219 -User root

```powershell
powershell -ExecutionPolicy Bypass -File .\build\deploy-to-server.ps1 -Server 123.123.123.123
```

脚本会自动完成以下操作：

1. 在本地打包 `backend`、`frontend`、`build` 和部署文档。
2. 通过 SCP 上传压缩包到服务器 `/tmp`。
3. 通过 SSH 创建服务器项目目录并解压文件。
4. 自动执行服务器上的 `build/install.sh`。
5. 完整清理旧服务、旧发布文件和旧数据库。
6. 重新构建并启动前后端服务。

如果服务器 SSH 端口不是 22：

```powershell
powershell -ExecutionPolicy Bypass -File .\build\deploy-to-server.ps1 -Server 123.123.123.123 -Port 2222
```

如果使用非 root SSH 用户，脚本仍然要求该用户能够无交互执行 root 操作。建议直接使用 root；如果必须使用普通用户，请先在服务器配置该用户的免密 `sudo`，并将脚本中的远程部署命令改为使用 `sudo`。

```powershell
powershell -ExecutionPolicy Bypass -File .\build\deploy-to-server.ps1 -Server 123.123.123.123 -User ubuntu
```

脚本默认上传到 `/opt/xn_ai_master`。如需修改服务器项目目录：

```powershell
powershell -ExecutionPolicy Bypass -File .\build\deploy-to-server.ps1 -Server 123.123.123.123 -RemoteProject /opt/xn_ai_master
```

## 四、手动上传项目

将整个项目上传到云服务器。推荐上传到：

```text
/opt/xn_ai_master
```

上传完成后，服务器上必须存在以下文件：

```text
/opt/xn_ai_master/build/install.sh
```

## 五、登录服务器

使用 SSH 登录云服务器：

```bash
ssh root@你的服务器IP
```

如果使用普通用户登录：

```bash
ssh 用户名@你的服务器IP
sudo -i
```

## 六、执行重新部署

进入项目目录：

```bash
cd /opt/xn_ai_master
```

确认部署脚本存在：

```bash
ls -l build/install.sh
```

增加执行权限：

```bash
chmod +x build/install.sh
```

执行完整清理和重新部署：

```bash
bash build/install.sh
```

也可以使用执行权限直接运行：

```bash
./build/install.sh
```

部署过程中不要关闭 SSH 窗口。脚本会自动完成系统依赖安装、旧服务清理、数据库重建、前后端构建、Nginx 配置和服务启动。

## 七、保存管理员账号密码

部署成功后，脚本会输出类似以下内容：

```text
[xn-platform] deployment completed
[xn-platform] url: http://服务器地址
[xn-platform] admin user: admin
[xn-platform] admin password: 随机生成的密码
```

请立即保存 `admin password`。本次重新部署会生成新的管理员密码。

管理员账号为：

```text
admin
```

## 八、访问系统

浏览器访问脚本输出的地址：

```text
http://你的服务器IP
```

例如：

```text
http://123.123.123.123
```

## 九、验证部署结果

### 1. 查看后端服务状态

```bash
systemctl status xn-platform
```

看到 `active (running)` 表示后端服务正在运行。

### 2. 查看后端实时日志

```bash
journalctl -u xn-platform -f
```

按 `Ctrl+C` 退出日志查看，不会停止后端服务。

### 3. 查看 Nginx 状态

```bash
systemctl status nginx
```

看到 `active (running)` 表示 Nginx 正常运行。

### 4. 检查 Nginx 配置

```bash
nginx -t
```

看到以下结果表示配置正确：

```text
syntax is ok
test is successful
```

### 5. 检查 3000 端口后端进程

```bash
ss -lntp | grep ':3000'
```

看到 Node.js 进程监听 `127.0.0.1:3000`，表示后端已经监听成功。

### 6. 检查 80 端口 Nginx 进程

```bash
ss -lntp | grep ':80'
```

看到 Nginx 进程监听 `0.0.0.0:80` 或 `[::]:80`，表示网页入口已经监听成功。

## 十、部署失败时的检查顺序

先查看后端日志：

```bash
journalctl -u xn-platform -n 100 --no-pager
```

再检查服务状态：

```bash
systemctl status xn-platform --no-pager
```

检查 Nginx：

```bash
nginx -t
systemctl status nginx --no-pager
```

检查 PostgreSQL：

```bash
systemctl status postgresql --no-pager
```

检查数据库是否已经创建：

```bash
sudo -u postgres psql -lqt | grep xn_platform
```

## 十一、再次重新部署

以后代码更新后，仍然使用相同命令：

```bash
cd /opt/xn_ai_master
bash build/install.sh
```

每次执行都会删除并重建 `xn_platform` 数据库，因此会清除系统中的管理员、MQTT 配置、设备数据和其他业务数据。
